# Anthropic 的 Agent 策略

> **AI 产业六层模型 · Agent 层 AGENT**
> 从模型到 MCP 协议、Claude Code 与可靠工具调用。
> 不做最炫的 Agent，做最可靠的 Agent 底座——用开放协议把生态变成护城河。

## 01 战略延伸：从「卖模型」到「卖会办事的能力」

Anthropic 把模型能力向上延伸为 Agent：不止回答问题，更能调用工具、操作系统、完成任务。

- **从对话到行动 · 工具调用**：模型可自主调用工具/API，把意图变成动作。
- **从单点到流程 · 任务编排**：跨步骤规划与执行，完成多环节任务。
- **从通用到专用 · Claude Code**：以编程 Agent 切入开发者高价值场景。
- **从封闭到开放 · MCP 协议**：用开放协议让能力可被发现与调用。

---

## 02 能力栈：Anthropic 的 Agent 能力栈

Agent = 模型能力 + 工具调用 + 上下文协议 + 开发框架，Anthropic 在每一层提供基础件。

| 层级 | 组件 | 说明 |
| --- | --- | --- |
| 模型层 | Claude | 强推理 + 可靠工具调用，是 Agent 的大脑 |
| 工具层 | Tool Use / Computer Use | 标准化工具调用，乃至直接操作电脑界面 |
| 协议层 | MCP | Model Context Protocol，连接数据与工具的开放标准 |
| 开发层 | Agent SDK | 构建、编排、部署 Agent 的开发框架与产品 |

---

## 03 商业模式：Agent 基础设施变现

Agent 让单次任务消耗更多 token、绑定更深的工作流，Anthropic 借此提升用量与客单价。

| 变现路径 | 价值跃迁 |
| --- | --- |
| API 工具调用：Agent 推理消耗更多 token | 从「按问答」到「按完成的任务」 |
| Claude Code：开发者订阅 + 用量 | Agent 嵌入工作流，粘性与切换成本上升 |
| 企业 Agent：安全、合规、私有化增值 | 可靠执行支撑「按结果」的高价值定价 |
| 平台/SDK：构建 Agent 的开发者生态 | 生态调用越多，模型用量越大 |

> **本质**：Agent 把模型从「被问」变成「被用来办事」，用量与价值随任务复杂度、工作流深度而放大。

---

## 04 产业护城河：可靠 · 安全 · MCP 网络效应 · 开发者入口

1. **可靠工具调用壁垒**：Agent 的关键是稳定地调对工具、少出错；模型可靠性直接决定可用性。
2. **安全与可控壁垒**：自主执行风险高，安全/护栏/可审计是企业敢用 Agent 的前提。
3. **MCP 网络效应**：开放协议被越多工具/数据源采用，连接价值越大，形成生态标准壁垒。
4. **开发者入口壁垒**：Claude Code 等抓住开发者，自下而上渗透企业 Agent 建设。

---

## 05 产业分工与判断：做「Agent 底座」，伙伴做垂直 Agent

Anthropic 选择做水平的能力底座（模型 + 协议 + SDK），把垂直场景让给生态伙伴。

| 产业分工 | 挑战与判断 |
| --- | --- |
| Anthropic：模型 + MCP + SDK 等底座 | Agent 可靠性/幻觉仍是采用门槛 |
| 伙伴/客户：在底座上做行业垂直 Agent | 巨头自带分发，底座竞争激烈 |
| MCP 连接第三方工具、数据与应用 | 协议标准之争（MCP vs 其他） |
| 云市场分发，触达企业 | 安全/合规是机会也是持续成本 |
| 与 OpenAI/Google 在 Agent 底座竞争 | 「可靠 + 开放」是 Anthropic 的差异打法 |

---

## 关键判断（Strategic Takeaways）

1. **可靠是 Agent 的第一性**：Agent 的胜负不在炫技，而在能否稳定、安全地把任务办成。
2. **协议即护城河**：MCP 若成事实标准，将以网络效应锁定生态，价值远超单个产品。
3. **做底座而非全包**：Anthropic 做水平能力底座，垂直场景交给生态，放大调用与用量。

---

> **结语**：把可靠与开放，做成 Agent 的护城河。当 Agent 成为新入口，Anthropic 以可靠执行 + MCP 开放协议，争夺 Agent 层的底座地位。
