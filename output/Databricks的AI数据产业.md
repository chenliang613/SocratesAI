## 01 公司定位：湖仓一体 + AI 原生

由 Apache Spark 创始团队创立，以「湖仓一体（Lakehouse）」统一数据工程、分析与 AI。

| 维度 | 关键点 | 说明 |
| --- | --- | --- |
| 基因 | Spark 创始团队 | 源自大数据/ML 工程，天然贴近 AI/数据科学 |
| 架构 | Lakehouse | Delta Lake 统一数据湖的灵活与数仓的可靠 |
| 人群 | 工程师/数据科学家 | 服务数据工程、ML 工程与 AI 开发者 |
| 主张 | 数据 + AI 一体 | 在同一平台完成从数据到模型的全流程 |

---

## 02 商业模式：数据 + AI 一体化平台

Databricks 同样采用消费式计费（DBU），但定位是「数据 + AI 全流程平台」而非单一数仓。

| 消费式定价 | 一体化增长 |
| --- | --- |
| 按 DBU（计算用量）计费，弹性付费 | 数据工程 → 分析 → ML → GenAI 一站式 |
| 覆盖数据工程、分析、ML、AI 全流程 | 减少多工具拼接，提升平台粘性 |
| 用量随数据 + AI 负载共同增长 | 开源（Spark/Delta/MLflow）引流转化 |
| 企业级治理（Unity Catalog）增值 | AI 负载成为新的用量增长极 |

> **本质**：用「一个平台覆盖数据到 AI 全流程」降低拼接成本，让数据团队与 AI 团队在同一底座协作。

---

## 03 模式对比：传统模式 vs Agentic 模式——数据 + AI 作业方式的跃迁

数据与 AI 的生产方式，正从「工程师手写管道与模型」转向「Agent 自主编排全流程」——作业主体、并发能力与平台用量被一并重构。

| 维度 | 传统模式 · 人建管道 | Agentic 模式 · Agent 建管道 |
| --- | --- | --- |
| 作业主体 | 工程师手写 notebook、调 pipeline、训模型 | Mosaic AI Agent / Genie 自主编排与生成 |
| 流程编排 | 人编排 ETL → 分析 → ML → GenAI 全流程 | Agent 自动跑 ETL、训练、评估、串流程 |
| 用量增长 | 消费随「数据团队手动作业量」增长 | 消费随「Agent 任务量」放大，DBU 激增 |
| 增长天花板 | 受限于工程师 / 数据科学家人数 | 天花板被打开，不再受限于人力 |
| 价值锚点 | 人构建数据与 AI 产物 | Agent 自动产出数据与 AI 成果 |

> **本质**：Agent 成为数据 + AI 全流程的「自主作业者」——在同一湖仓底座上并发跑管道与模型，把一体化平台的用量天花板进一步抬高。对 Databricks 而言，Agentic 化让「数据 + AI 一体」从开发体验优势升级为用量增长引擎。

## 04 AI 战略：从「跑别人的模型」到「造自己的模型」

Databricks 通过收购 MosaicML 切入模型训练，主张企业用自有数据低成本定制专属模型。

- **Mosaic AI · 训练/定制**：收购 MosaicML，支持企业低成本训练专属模型。
- **DBRX · 开放模型**：推出开放权重模型，强化 AI 原生心智。
- **MLflow · 全生命周期**：开源 MLOps 标准，管理模型实验到部署。
- **Unity Catalog · 统一治理**：数据 + 模型 + AI 资产的统一权限与血缘。

## 05 产业护城河：开放湖仓 · AI 原生 · 开源 · 一体化

1. **开放湖仓壁垒**：Delta Lake 等开放格式，避免厂商锁定，赢得工程团队信任。
2. **AI/ML 原生壁垒**：从数据到模型的全流程能力，在 GenAI 时代天然占位。
3. **开源生态壁垒**：Spark / Delta / MLflow 的广泛采用，构成事实标准与人才基础。
4. **一体化粘性壁垒**：数据 + AI 一站式 + 统一治理，迁移与替换成本高。

## 06 产业分工与竞争：vs Snowflake——定位差异与判断

Databricks 与 Snowflake 同处数据平台层，但切入人群与哲学不同，正面向对方腹地扩张。

| 分工与差异 | 挑战与判断 |
| --- | --- |
| 面向工程师/数据科学家（vs 分析师/SQL） | 与 Snowflake 双向入侵、正面交锋 |
| 开放湖仓架构（vs 托管数仓体验） | 云厂商既是底座也是竞争者 |
| AI/ML 原生（vs 分析起家后补 AI） | 易用性需向业务用户进一步下沉 |
| 同样多云，租用超大规模云基础设施 | 开源养生态但需平衡商业化 |
| 自有模型能力（MosaicML）是差异点 | AI 原生 + 自有模型是长期胜负手 |

## 08 竞争格局：数据 + AI 平台的多方争夺

Databricks 侧有 Snowflake 相向竞争，上有云 ML 平台夹击，并与数据工具链既合作又重叠。

| 对手 / 定位 | 打法 | 说明 |
| --- | --- | --- |
| Snowflake | 数据云/托管 | 从分析师/SQL 侧相向竞争，易用性是其优势 |

| 数据基础设施 | Confluent/dbt 等 | 上下游工具，既合作又部分重叠 |

## 10 护城河风险 vs 独特价值与客户粘性

与 Snowflake 正面交锋、云厂商夹击，但一体化 + 统一治理 + 开源生态的粘性极强。

| 护城河面临的风险 | 独特价值与客户粘性 |
| --- | --- |
| 与 Snowflake 双向入侵、正面交锋 | 数据 + AI 一站式，减少多工具拼接 |
| 云厂商既是底座也是竞争者 | Unity Catalog 统一治理，资产血缘锁定 |
| 易用性需向业务用户进一步下沉 | 开源（Spark/Delta/MLflow）= 人才与标准 |
| 开源养生态但需平衡商业化变现 | 工程/ML 团队习惯沉淀，迁移成本高 |
| 模型训练投入大，回报周期长 | 自有数据定制模型，深度绑定客户数据 |

> **本质**：一体化粘性——把数据到模型的全流程 + 统一治理收进一个平台，换平台 = 换整套工作流。

---

## 关键判断（Strategic Takeaways）

1. **AI 原生是先发优势**：从 Spark/ML 起家，Databricks 在数据 + AI 一体化上天然占位。
2. **Agentic 放大平台用量**：Agent 自主跑数据 + AI 全流程，把 DBU 用量从「人力上限」推向「任务量驱动」，成为一体化平台的新增长极。
3. **开放对抗锁定**：开放湖仓 + 开源生态，是其对抗托管型对手与云厂商的核心武器。
4. **与 Snowflake 殊途同归**：两者从不同人群相向扩张，最终争夺「企业数据 + AI 底座」。
