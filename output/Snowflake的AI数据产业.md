## 01 公司定位：从云数据仓库到「数据云」

以「存算分离 + 多云 + 极致易用」起家，目标是成为企业数据的统一底座与流通网络。

| 维度 | 关键点 | 说明 |
| --- | --- | --- |
| 起点 | 云数据仓库 | 存储与计算解耦，弹性伸缩、按需付费 |
| 架构 | 多云中立 | 横跨 AWS/Azure/GCP，不绑定单一云 |
| 体验 | 极致易用 | 近乎免运维，SQL 分析师即可上手 |
| 愿景 | 数据云 | 从「存数据」走向「数据共享与流通网络」 |

---

## 02 商业模式：按消费计费的数据云

Snowflake 采用消费式定价（按计算 credit 计费），收入与客户用量同频增长。

| 消费式定价 | 增长引擎 |
| --- | --- |
| 按计算资源消耗（credit）计费，用多少付多少 | 数据上云后，分析负载持续增长 |
| 存储与计算分别计价，弹性可控 | 数据共享/Marketplace 带来新用量 |
| 净收入留存率高，客户用量自然扩张 | AI/应用负载（Cortex/Snowpark）拉动消费 |
| 定价与客户价值同向，降低采用门槛 | 「数据进来就出不去」的引力效应 |

> **本质**：把定价与客户用量绑定，让平台收入随「数据被用得越多」而自然增长——数据引力即增长引擎。

## 03 模式对比：传统模式 vs Agentic 模式——数据消费逻辑的跃迁

数据平台的价值实现，正从「人主动查询数据」转向「Agent 自主调用数据」——消费的主体、节奏与天花板被一并重构。

| 维度 | 传统模式 · 人查数据 | Agentic 模式 · Agent 用数据 |
| --- | --- | --- |
| 消费主体 | 分析师写 SQL / BI，由人主动发起查询 | Cortex Agent 自主查询、分析、产出洞察 |
| 调用节奏 | 数据被动等待被人调用、被人解读 | Agent 7×24 主动调用数据、串联流程 |
| 用量增长 | 消费随「人的分析工作量」线性增长 | 消费随「Agent 任务量」指数级放大 |
| 增长天花板 | 受限于分析师人数与上班节奏 | 天花板被打开，不再受限于人力 |
| 价值锚点 | 人看报表、再做决策 | Agent 自动产出洞察与行动 |

> **本质**：Agent 成为数据的「超级消费者」——自主、并发、7×24 地调用数据，把消费式定价的增长天花板彻底抬高。对 Snowflake 而言，Agentic 化不是成本，而是用量的新增长极。

## 04 AI 战略：Cortex——把 AI 带到数据旁，而非把数据搬向 AI

Snowflake 的 AI 主张是「让模型在数据所在地运行」，减少数据搬运、保障治理与安全。

- **Cortex AI · 内置 LLM**：在平台内直接调用大模型，贴着数据做生成与分析。
- **Snowpark · 多语言开发**：Python 等在数据侧运行，支撑 ML 与数据应用。
- **向量与检索 · RAG 底座**：向量存储与检索，支撑企业知识库与 RAG。
- **治理优先 · 数据不出域**：权限、审计、合规贯穿，AI 在可信边界内运行。

## 05 产业护城河：易用 · 引力 · 共享 · 中立

1. **易用性壁垒**：近免运维 + SQL 友好，降低采用门槛，赢得分析师与业务用户。
2. **数据引力壁垒**：数据沉淀越多、迁移成本越高，消费随负载增长形成正反馈。
3. **数据共享网络效应**：数据 Marketplace 与跨组织共享，参与者越多价值越大。
4. **多云中立壁垒**：不绑定单一云，成为客户对冲云厂商的「中立数据层」。

## 06 产业分工与判断：站在超大规模云之上

Snowflake 是「云之上的数据层」：依赖超大规模云的基础设施，同时与其数据产品正面竞争。

| 分工与依赖 | 挑战与判断 |
| --- | --- |
| 底层算力/存储租用 AWS/Azure/GCP | 云厂商既是房东也是对手，毛利受挤压 |
| 与云自有数仓（Redshift/BigQuery）竞争 | Databricks 在 AI/ML 场景强势竞争 |
| 与 Databricks 争夺数据平台心智 | 消费式定价下成本透明度受客户关注 |
| 上接 BI、AI、应用生态做分发 | 需从「分析」延伸到「AI + 应用」 |
| 中立定位是相对云厂商的差异点 | 数据引力 + 共享网络仍是核心护城河 |

Snowflake 上有云自带数仓夹击，侧有 Databricks 相向竞争，下有传统数仓存量待替换。

| 对手 / 定位 | 打法 | 说明 |
| --- | --- | --- |
| Databricks | 湖仓 + AI 原生 | 从工程/ML 侧相向竞争，AI 原生是其优势 |

| Snowflake 定位 | 易用 + 中立 + 共享 | 托管易用 + 多云中立 + 数据共享网络 |

## 10 护城河风险 vs 独特价值与客户粘性

纯数仓定位在 AI 原生时代面临挤压，但数据引力与共享网络的粘性极强。

| 护城河面临的风险 | 独特价值与客户粘性 |
| --- | --- |
| 云厂商既是房东也是对手，毛利受挤压 | 数据沉淀越多迁移成本越高（数据引力） |
| Databricks 在 AI/ML 场景强势竞争 | 近免运维 + SQL 友好，业务用户离不开 |
| 消费式定价下成本透明度受关注 | 数据共享/Marketplace 网络效应 |
| 需从「分析」延伸到「AI + 应用」否则被绕过 | 跨组织数据协作一旦建立难以替换 |
| AI 原生时代，纯数仓定位可能被边缘化 | Cortex 让 AI 贴着数据，数据不出域省搬运 |

> **本质**：数据引力 + 共享网络让「数据进来就出不去」，这是 Snowflake 最强的粘性。

---

## 关键判断（Strategic Takeaways）

1. **易用 + 消费式是增长底盘**：低门槛上手 + 用量计费，让收入随数据被用得越多而增长。
2. **Agentic 抬高消费天花板**：Agent 成为数据的超级消费者，把用量从「人力上限」推向「任务量驱动」，是消费式定价的新增长极。
3. **护城河在数据引力与共享**：数据沉淀的迁移成本 + Marketplace 网络效应，是真正的壁垒。
4. **AI 贴着数据走**：Cortex 把 AI 带到数据旁，治理与安全是其相对通用 AI 的差异。

---

> **结语**：数据的引力，就是平台的护城河。让数据即取即用、可被共享，Snowflake 用易用性与网络效应，守住数据平台层的入口。
